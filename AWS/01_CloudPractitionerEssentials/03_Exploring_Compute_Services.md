## サーバーレスコンピューティングの概要
### ①アンマネージドサービス
- 顧客の責任が多い
- 下記は`顧客`の責任
  - プラットフォームとアプリケーションの管理
  - OS、ネットワーク、ファイアウォールの設定
### ②マネージドサービス
- 顧客の責任が少ない
- 下記は`AWS`の責任
  - プラットフォームとアプリケーションの管理
  - OS、ネットワーク、ファイアウォールの設定
- 運用上のオーバーヘッドの大部分は AWS が対処するが、サービスによってはお客様によるプロビジョニングや設定の必要性が残る場合がある
### ③フルマネージドサービス
- 顧客は、下記にのみ責任を持つ
  - 顧客のデータ
  - クライアント側のデータ暗号化
- サーバーのプロビジョニングや管理はすべてAWSで行う

## AWS Lambda
#### Lambdaとは
- サーバーのプロビジョニングや管理が不要
- イベントに応答してコードを実行できる
- サーバーレスのコンピューティングサービス  
  
＝＝＝＝＝＝＝＝＝＝＝＝＝＝＝＝＝＝＝＝＝＝＝＝
- 基盤となるインフラストラクチャは自動的に管理される
- リクエストの量に基づいてリソースがスケール（拡大・拡張）される  
  
＝＝＝＝＝＝＝＝＝＝＝＝＝＝＝＝＝＝＝＝＝＝＝＝
  
- 料金は、ミリ秒単位
- 消費されたコンピューティング時間に対してのみ課金される  
＝＝＝＝＝＝＝＝＝＝＝＝＝＝＝＝＝＝＝＝＝＝＝＝
- コードの実行、スケーリング、およびリソース割り当ては Lambda によって行われる
- 顧客は、関数に適したメモリサイズを設定することで、パフォーマンスを最適化できる
- 顧客は、データへのアクセス許可の管理責任を持つ
#### Lambdaのしくみ
1. コードをLambdaにアップロードする  
   - アップロードされるコードは、`Lambda関数`と呼ばれる
   - Lambda関数の最大実行時間 = 15分
2. イベントソースからトリガーされるようにコードを設定する  
3. トリガーされた時にコードを実行する  
4. 使用したコンピューティング時間分のみ料金を支払う  
   - ミリ秒単位で、消費されたコンピューティング時間に対してのみ課金される
   - 料金は、関数に割り当てるメモリ容量によって異なる

## AWS におけるコンテナとオーケストレーション
### コンテナとは
- アプリケーションのコードと依存関係を 1 つの移植可能な単位にパッケージ化できる高信頼の手法
- 高いセキュリティ、信頼性、スケーラビリティを必要とするワークフローに最適

#### コンテナとVM（仮想マシン）
🚅 コンテナ
- アプリケーションの実行に必要なすべてのものがパッケージ化される
- どのコンピュータでも同じように機能する
- アプリケーションの移行、更新、管理に役立つ
- コンテナは仮想マシン (VM) と比べて高速であり、軽量  
  → コンテナ間ではホストコンピュータのオペレーティングシステムを共有するため
🚃 VM
- リソース効率がそれほど高くなく、起動に時間がかかる  
  → ハイパーバイザーを使用して完全に独立したオペレーティングシステムを実行するため
#### コンテナによるデプロイの一貫性
- デベロッパーの環境がステージング環境や本番環境と異なる場合、デプロイが失敗し、そのデバッグが困難になることがある
- コンテナは、どのような場所でもアプリケーションの実行環境に一貫性を持たせることでこの問題を解決し、デプロイの円滑化とトラブルシューティングに役立つ

#### オーケストレーションによるコンテナのスケーリング
- コンテナ化されたアプリケーションの規模が拡大すると、それらを管理する複雑性が増大する
- コンテナが膨大になると、コンテナのライフサイクル、モニタリング、全般的な運用を手動で行う体制が維持できなくなる  
  ↓  ↓  
`オーケストレーションツール`を使用して解決できる。  
→ コンテナのデプロイ、スケーリング、管理を自動化し、すべてを円滑に実行できるようになる

### AWS コンテナサービス
#### 🐋 Amazon ECS（Elastic Kubernetes Service）
- コンテナオーケストレーションサービス
- Docker コンテナのようなコンテナを AWS 上で実行および管理する

##### Amazon ECS 起動タイプ
▼  `Amazon ECS` と `Amazon EC2` の組み合わせ  
- インフラストラクチャを完全に制御する必要がある中小規模の企業に最適
- Amazon EC2 の柔軟性と Amazon ECS のシンプルさは、特定のハードウェアやネットワーク構成を必要とするカスタムアプリケーションに適する
  
▼ `Amazon ECS` と `AWS Fargate` の組み合わせ  
- トラフィックが変動するウェブアプリケーションを構築するスタートアップ企業や小規模チームに最適
- サーバー管理を必要としないサーバーレスのオプション
- Amazon ECS によってスケーリングとオーケストレーションが処理されるため、チームは開発に集中できる

#### 🧑‍💼Amazon EKS（Elastic Kubernetes Service）
- AWS 上で Kubernetes を実行するのに使用できる、フルマネージドサービス
- Kubernetes(幅広いコミュニティから継続的なサポートと更新が提供されるオープンソース) を使用
- コンテナ化されたアプリケーションのデプロイ、管理、スケーリングを簡素化する
##### Amazon EKS 起動タイプ
▼ `Amazon EKS` と `Amazon EC2`
- インフラストラクチャを完全に制御する必要がある企業に最適
- EC2 インスタンスの高度なカスタマイズ性と Kubernetes のスケーラビリティは、複雑で大規模なワークロードに最適

▼ `Amazon EKS` と `AWS Fargate`
- サーバーの管理を行うことなく Kubernetes の柔軟性を求めるチームに最適
- Kubernetes の強力な機能とサーバーレスのシンプルさを組み合わせることで、さまざまなユースケースでアプリケーションを迅速にスケールできる


#### 📁Amazon ECR（Elastic Container Registry）
- コンテナイメージを保存、管理、デプロイするためのサービス
- オープンコンテナイニシアチブ (OCI) 標準に準拠したコンテナイメージをサポート
- 標準的なコンテナツールやコマンドラインインターフェイス (CLI) を使用して、Amazon ECR リポジトリに対するイメージのプッシュ、プル、管理ができる


#### 🧑‍🤝‍🧑Fargate
- コンテナ用のサーバーレスのコンピューティングエンジン
- Amazon ECS および Amazon EKS の両方と連携する
- Fargate はコンテナのホスティングプラットフォームであり、Amazon ECS や Amazon EKS のようなコンテナのオーケストレーションサービスではない  
  ＝＝＝＝＝＝＝＝＝＝＝＝＝＝＝＝＝＝＝＝＝＝＝＝
- Fargate を使用するにあたり、サーバーのプロビジョニングや管理は不要
- サーバーのインフラストラクチャの管理は、ユーザーに代わって Fargate が行う
- ユーザーはより多くの時間をアプリケーションの開発や刷新に注ぐことができる
- 料金は、コンテナの実行に必要なリソースに対してのみ発生

## その他のコンピューティングサービス
### Elastic Beanstalk
- `ウェブアプリケーションのデプロイ、管理、スケーリングを効率化`するフルマネージドサービス
- デベロッパーはコードをアップロードするだけで、Elastic Beanstalk によってインフラストラクチャのプロビジョニング、スケーリング、ロードバランシング、アプリケーションのヘルスモニタリングが自動的に処理される
- Java、.NET、Python、Node.js、Docker など、さまざまなプログラミング言語およびフレームワークがサポートされている
- 基盤となる AWS リソースを完全に制御しながら、多くの運用タスクを自動化できる
#### ▽ 適した用途
- ウェブアプリケーション
- RESTful API
- モバイルバックエンドサービス
- マイクロサービスアーキテクチャを対象とするデプロイと管理 (スケーリングの自動化とインフラストラクチャ管理の簡素化を伴う)
### AWS Batch
- AWS 上で`バッチコンピューティングワークロード`を実行するためのフルマネージドサービス
- バッチジョブ用のコンピューティングリソースのスケジューリング、管理、スケーリングを自動的に行う
- ジョブの要件に基づいてリソース割り当てを最適化する
#### ▽ 適した用途
下記などの分野における`大規模な並列ワークロード`の処理
- 科学計算
- 金融リスク分析
- メディアトランスコーディング
- ビッグデータ処理
- 機械学習トレーニング
- ゲノミクス研究
### Lightsail
- 仮想プライベートサーバー (VPS)、ストレージ、データベース、ネットワークを`予測可能な月額料金`で提供するクラウドサービス
- 下記顧客において最適
  - 小規模ビジネス
  - 基本的なワークロード
  - シンプルなAWS操作環境を求めているデベロッパー
#### ▽ 適した用途
- 基本的なウェブアプリケーション
- 低トラフィックのウェブサイト
- 開発環境およびテスト環境
- 小規模企業のウェブサイト
- ブログ
- 学習用クラウドサービス
### Outposts
- AWS のインフラストラクチャとサービスを`オンプレミス(自社)のデータセンターに拡張`するフルマネージド型のハイブリッドクラウドソリューション
- コンピューティング、ストレージ、ネットワークのコンポーネントを提供
- オンプレミスと AWS クラウド間で一貫性のある環境を提供
#### ▽ 適した用途
- 低レイテンシーアプリケーション(レイテンシ=遅延時間)
- 遠隔地でのデータ処理
- レガシーアプリケーションの移行やモダナイズ（刷新）
- 規制コンプライアンスやデータレジデンシーの要件への対応
